Vidow v2.0 is built on the Manifest V3 extension platform and supports all major Chromium-based desktop browsers.

## Browser compatibility

| Browser | macOS | Windows | Linux | Status |
|---------|-------|---------|-------|--------|
| **Google Chrome** | Yes | Yes | Yes | Fully supported |
| **Microsoft Edge** | Yes | Yes | Yes | Fully supported |
| **Brave** | Yes | Yes | Yes | Fully supported |
| **Mozilla Firefox** | — | — | — | Coming soon |

## Operating system support

- **macOS** — 10.15 Catalina and later
- **Windows** — Windows 10 and later
- **Linux** — Any distribution capable of running a supported Chromium-based browser

## Mobile support

Browser extensions are a desktop-only technology. Vidow cannot be installed on mobile browsers including iOS Safari, Chrome for Android, or any in-app browser. Mobile platform support is not currently planned.

## Minimum browser versions

Vidow requires Manifest V3 support, which was introduced in these versions:

- **Chrome** 88 or later
- **Edge** 88 or later
- **Brave** 1.20 or later

Running an older version? Update your browser to the latest stable release to ensure full compatibility.

## Language support

Vidow is localized into 59 languages. The extension automatically matches your browser's language setting — no manual selection required. Supported languages include:

English, French, Arabic, Spanish, German, Portuguese, Chinese (Simplified), Japanese, Korean, Hindi, Russian, Italian, Dutch, Turkish, Polish, and 44 additional languages.

## Extension permissions

When you install Vidow, the browser asks you to approve a set of permissions. Here is what each one is used for:

| Permission | Purpose |
|------------|---------|
| **tabs** | Associate detected streams with the correct browser tab, update the detection badge when you switch tabs, and clean up stream data when a tab is closed |
| **webRequest** | Monitor network responses to identify video streams — HLS manifests, DASH segments, and direct MP4 files — by inspecting Content-Type headers and URL patterns |
| **declarativeNetRequest** | Used as a fallback download mechanism and to manage streaming bridge headers when direct network interception is insufficient |
| **storage** | Save your preferences, detected stream data for the current session, and authentication state locally on your device |
| **downloads** (optional) | Enable saving files through the browser's download dialog with proper file names and folder routing — this permission is only requested when you turn on download management in settings |
| **all_urls** (host permission) | Detect video streams on any website — required because video content can be hosted on any domain, not just a fixed list of known platforms |

<Info>
  Page URLs may be sent to Vidow servers on certain websites where network-level interception alone cannot identify streams. This is used exclusively for fallback stream detection.
</Info>

## Why Chromium only?

Vidow relies on a set of browser APIs that are currently stable only in Chromium-based browsers:

- **`webRequest`** — Low-level network monitoring needed to identify streams in real time as pages load
- **`declarativeNetRequest`** — Declarative download rules and header manipulation for reliable file saving
- **`storage.sync`** — Settings that synchronize automatically across all your browser profiles and devices
- **Background service worker** — Persistent processing without a persistent background page, keeping resource use low

Firefox exposes some equivalent APIs through the WebExtension standard, but the behavior diverges enough that a separate implementation is required. Firefox support is currently in development.
